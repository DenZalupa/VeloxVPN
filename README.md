# VeloxVPN

Настольный клиент VPN для Windows: **быстрая проверка узлов**, **настоящее окно**
и **автовосстановление интернета** при сбоях.

[![Python](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)
[![Windows](https://img.shields.io/badge/platform-Windows-0078D6.svg)](https://www.microsoft.com/windows)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

---

## Что это

Настольный клиент VPN для Windows, который делает три вещи лучше большинства
аналогов: **очень быстро проверяет узлы**, **не заставляет ждать** и **не оставляет
вас без интернета**.

Обычные клиенты пингуют серверы последовательно или 3–5 потоками — на 100 узлов
уходит 30–60 секунд. Здесь используется асинхронный параллельный TCP/TLS-движок
(до 80–100 одновременных соединений), поэтому сотня серверов проверяется
**меньше чем за 1.5 секунды**, а карточки в списке обновляются на лету через WebSocket.

Второе: приложение живёт **в системном трее**. Закрыл окно — VPN продолжает
работать, статус виден по иконке, соединение отключается одним кликом.

Третье: интерфейс — **настоящее окно Windows** на движке WebView2, без
адресной строки, вкладок и фонового браузера. Никакого Edge в процессах.

Четвёртое: если программа упала или её убили — **интернет восстанавливается сам**.

## Возможности

### Главный экран — минимализм

На главном экране осталось ровно то, что нужно в первую очередь: **одна большая
кнопка подключения** и **три метрики**.

- **Одна кнопка** «Подключиться / Отключиться». Внутри кнопки — текущее состояние:
  «Отключено», «Подключение…», «Подключено» или «Ошибка». Цвет, текст,
  `aria-label` и `aria-pressed` меняются вместе с состоянием.
- **Подпись под кнопкой** — к какому серверу подключимся (или к какому подключены),
  ниже — подсказка действия, время сессии и реальная задержка в сети.
- **Три метрики** ровно в одной строке:
  1. **Тест пинга** — параллельная проверка всех узлов;
  2. **Замер скорости** — экспресс-тест через Cloudflare CDN;
  3. **Текущая скорость** — live throughput (вниз/вверх) и суммарный трафик за сессию.

  Плитки никогда не скрываются — меняются только значения, поэтому layout не «прыгает».
- Кнопка подключается сама к лучшему серверу: избранный с лучшим пингом, иначе —
  самый быстрый из всех. Текущий фильтр в окне серверов на выбор не влияет.

Всё остальное вынесено из главного экрана, но **ничего не удалено**:

| Куда | Что переехало |
|---|---|
| **«Серверы»** | весь список, поиск, сортировка, вкладки категорий, чипсы-фильтры, избранное, удаление |
| **«Подписки»** | ссылки на подписки, обновление всех подписок, быстрый импорт ключей |
| **«Настройки»** | маршрутизация, TUN-режим, параметры пинга, список «мимо VPN», системный прокси, восстановление интернета, логи, счётчики дедупликации |

- Адаптивно: на узких экранах метрики складываются в одну колонку, кнопка
  уменьшается, но остаётся главным элементом.
- Доступность: видимое кольцо фокуса, работа с клавиатуры, `aria-label`,
  `aria-pressed` и `aria-busy` у главной кнопки, контрастные состояния.
- Без внешних CDN и без новых зависимостей — только системные шрифты и
  монохромные inline-SVG-иконки.

### Дедупликация серверов

Одинаковые по подключению серверы не показываются дважды — но только если они
действительно одинаковые.

- Канонический ключ: **протокол + нормализованный host + порт (с дефолтом
  протокола) + транспорт (network) + security + SNI + параметры подключения
  и учётные данные** (uuid / public key / пароль и т.п.), а также path.
- Host нормализуется: нижний регистр, без лишней точки в конце, IPv6
  приводится к каноническому виду.
- Отображаемое имя **не является** идентификатором: серверы с одинаковым
  названием, но разными портами, протоколами, транспортом или учётными
  данными остаются разными.
- Правило применяется при загрузке списка, импорте, обновлении подписок,
  добавлении и перед генерацией конфига. Повторный запуск ничего не меняет
  (идемпотентно), сложность близка к O(n).
- При объединении дублей сохраняются полезные метаданные: лучшее имя,
  последний пинг, отметка «белый список» и избранное. Если активный или
  выбранный сервер оказался дублем — выбор переназначается на оставшийся
  экземпляр, подключение не сбрасывается.
- Пользователь видит счётчик: в настройках — «Серверов в списке» и
  «Дубликатов исключено», в тосте — короткий суффикс «· исключено N дубликат(а/ов)».
  Уведомления не спамятся: счётчик обновляется, а тост добавляется один раз.
- В логи не попадают пароли, приватные ключи, UUID и другие секреты.

### Сводка по подписке

Главный экран показывает состояние подписки прямо под кнопкой подключения:

- **Израсходовано / осталось** — «Израсходовано 387 ГБ из 2048 ГБ · осталось 1661 ГБ (18.9%)»;
- **Прогресс-бар** расхода пакета: при 70% и 90% он меняет цвет на предупреждающий;
- **Срок действия** — «до 23.12.2026 · 28 дн.»;
- Та же сводка — в окне «Подписки» для каждой подписки отдельно.

Данные берутся из стандартного HTTP-заголовка `Subscription-Userinfo`
(`upload`, `download`, `total`, `expire`), который отдают панели v2ray/XRay.
Сводка обновляется при обновлении подписок и автоматически раз в 30 минут —
запрашиваются только заголовки, тело ответа не скачивается.

Если провайдер не отдаёт эти данные, блок просто не показывается —
выдуманных цифр не бывает. Одна и та же подписка не может быть добавлена
дважды, иначе трафик в сводке удваивался бы.

### Тёмная и светлая тема

- Переключатель темы — иконка в шапке окна (солнце / луна).
- Выбор сохраняется локально и в настройках приложения, поэтому тема
  переживает перезапуск.
- Тёмная тема сохраняет тот же «жидкий стекло»-стиль: матовые панели,
  монохромные иконки, тот же ритм и воздух.

### Протоколы

- `vless://` — в т.ч. **VLESS Reality**, XTLS Vision, WebSocket, gRPC
- `vmess://` — Base64 JSON
- `trojan://` — с TLS и Reality
- `ss://` — Shadowsocks 2022, AEAD, chacha20, aes
- `hysteria2://` / `hy2://`

### Проверка узлов

- Параллельный асинхронный пинг всех серверов разом
- Живое обновление карточек во время теста (WebSocket)
- Сортировка по пингу, странам, названию и протоколу
- Реальная задержка интернета через прокси (Cloudflare / Google 204)
- Избранное, фильтр «только онлайн», поиск по названию и стране

### Маршрутизация

- **Обход РФ (Smart Rule)** — российские сайты, банки, Госуслуги, VK и Яндекс идут
  напрямую на скорости провайдера, заблокированные ресурсы — через VPN
- **Global** — весь трафик через выбранный узел
- **Direct** — прямое подключение без VPN
- **Свой список «мимо VPN»** — домены, поддомены, приложения и подсети,
  которые всегда идут напрямую:
  ```
  youtube.com      домен и его поддомены
  *.vk.com         все поддомены
  steam.exe        трафик конкретного приложения
  192.168.0.0/16   целая подсеть
  ```

### Интеграция с Windows

- Управление системным прокси (WinINet) — браузеры и приложения подхватывают
  VPN автоматически
- **TUN-режим** — весь сетевой трафик компьютера (игры, Telegram, Discord) идёт
  через VPN, а не только трафик браузеров
- Автосброс системного прокси при отключении и при закрытии программы
- **Иконка в системном трее**: статус подключения, быстрое подключение/отключение,
  открытие окна, восстановление сети, корректный выход с очисткой прокси

### Защита от «мёртвого» интернета

Главная боль Windows-клиентов: программа включила системный прокси, а потом упала —
и интернет в системе пропал до повторного запуска программы. Здесь это исправлено:

- **Сторож (guardian)** — отдельный процесс, который переживает гибель основного
  приложения. Через несколько секунд после `taskkill /F` или краша он сам выключает
  зависший прокси, убивает осиротевшее ядро `sing-box` и удаляет осиротевший
  TUN-адаптер. Интернет возвращается сам.
- **Watchdog внутри приложения** — если ядро `sing-box` умерло, а программа ещё жива,
  прокси гасится автоматически.
- **Автовосстановление при запуске** — если после прошлого аварийного выхода остался
  прокси на «мёртвый» порт, он сбрасывается при старте.
- **Кнопка «Починить»** в настройках и в трее — ручной сброс прокси, ядра
  и TUN-адаптера.
- **`Починить интернет.bat`** — отдельная утилита, если программа вообще не запускается.
- **Ваш прежний прокси не теряется**: перед включением своего прокси программа
  запоминает настройки пользователя (например, Clash) и возвращает их при отключении.

### Интерфейс

- Светлая тема «жидкого стекла»: матовые полупрозрачные панели, мягкие тени,
  монохромные иконки, системная типографика
- **Тёмная тема** с переключателем в шапке — выбор сохраняется между запусками
- **Нативное окно Windows** на движке WebView2 (pywebview): без адресной строки,
  вкладок и фонового браузера — приложение выглядит и ведёт себя как обычная
  программа (как HAPP или Incy)
- Закрытие окна сворачивает приложение в трей, а не завершает его;
  «Выход» в трее закрывает по-настоящему
- Если WebView2 недоступен — автоматический откат на окно Edge в app-режиме

## Быстрый старт

```bash
git clone https://github.com/YOUR_USERNAME/VeloxVPN.git
cd VeloxVPN
pip install -r requirements.txt
python main.py
```

Или просто запустите готовую сборку: `VeloxVPN\VeloxVPN.exe`.

### Требования к системе

- Windows 10/11 (x64)
- Python 3.9+ — только для запуска из исходников
- [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) —
  для нативного окна; в сборке EXE ставится отдельно, если его ещё нет
- Ядро **sing-box** и драйвер **Wintun** — приложение скачивает их сам или
  их можно положить в папку `bin\` вручную

## Сборка .exe

```bat
build_exe.bat
```

Скрипт собирает `VeloxVPN\VeloxVPN.exe` (одинарный каталог, `--uac-admin`,
WebView2 через pywebview + pythonnet). Ручной вызов:

```bat
pyinstaller --noconfirm --clean --onedir --windowed --uac-admin ^
  --name VeloxVPN --icon "app.ico" ^
  --add-data "static;static" --add-data "bin;bin" ^
  --hidden-import pystray --hidden-import pystray._win32 --collect-submodules pystray ^
  --hidden-import clr --hidden-import webview --collect-submodules webview ^
  --collect-all pythonnet --collect-all clr_loader ^
  --distpath "." --workpath "build_guard" main.py
```

> Флаги для `pythonnet`, `clr_loader` и `webview` обязательны: без них нативное
> окно WebView2 не стартует из собранного EXE.

├── data/                   Личные данные (не в репозитории!)

## Тесты

```bash
python tests/test_all.py
```

Набор покрывает: whitelist-детектор, определение страны, разбор всех URI,
парсер bypass-правил, сборку конфига sing-box (включая TUN, Clash API,
Kill Switch и DoH), извлечение ключей, быстрый пинг, самовосстановление сети,
потокобезопасность хранилища, speed test и счётчики трафика, трей,
**движок дедупликации** (ключи, метаданные, идемпотентность, сохранность
выбранного сервера) и **сводку по подписке** (разбор заголовков
`Subscription-Userinfo`, защита от удвоения трафика при дублях подписок).

Тесты работают на изолированном временном хранилище и **не трогают**
`data/app_config.json` — реальные подписки и ключи пользователя не страдают.

## Как выложить на GitHub

### Самый простой способ — `publish.bat`

Двойной клик по **`publish.bat`** в папке проекта: скрипт создаст (или обновит)
репозиторий, зальёт исходники и соберёт релиз со сборкой Windows.

Перед первым запуском нужен **Personal Access Token (classic)**:

1. GitHub → **Settings** → **Developer settings** → **Personal access tokens**
   → **Generate new token (classic)**.
2. Отметить галочку **`public_repo`** (для публичного репозитория).
3. Создать файл `%USERPROFILE%\.velox_github_token` и вставить в него токен
   одной строкой. Файл лежит вне репозитория, в git он не попадает.

После этого:

```bat
publish.bat
```

Скрипт спросит имя репозитория (по умолчанию `VeloxVPN`) и опубликует проект.
Открыть репозиторий: `https://github.com/<ваш-логин>/VeloxVPN`.

### Вручную, без bat-файла

```bat
python publish_github.py --repo VeloxVPN --visibility public --release
```

Полезные ключи:

| Ключ | Назначение |
|---|---|
| `--repo ИМЯ` | имя репозитория (по умолчанию `VeloxVPN`) |
| `--visibility public\|private` | видимость нового репозитория |
| `--org ОРГАНИЗАЦИЯ` | публиковать в организацию, а не в личный аккаунт |
| `--release` | собрать релиз и приложить zip со сборкой |
| `--dry-run` | только показать, какие файлы уйдут на GitHub, ничего не отправляя |

Токен читается из переменной окружения `GITHUB_TOKEN` (или `GH_TOKEN`),
иначе — из файла `%USERPROFILE%\.velox_github_token`. В репозиторий он не
копируется и в логи не попадает.

### Как это работает

`publish_github.py` ходит напрямую в **REST API GitHub** (без `git` и без
`gh` — их не нужно устанавливать) и использует Git Data API:

1. **blob** — каждый файл загружается как отдельный блоб;
2. **tree** — из блобов собирается дерево;
3. **commit** — создаётся коммит с этим деревом;
4. **ref** — указатель ветки `main` переносится на новый коммит.

Скрипт **уважает `.gitignore`**: личные данные (`data/`), ядра sing-box и
Wintun (`bin/*`), локальные сборки (`/VeloxVPN/`) и zip-архивы релизов
в репозиторий не попадают. Перед публикацией можно проверить состав
файлов: `python publish_github.py --dry-run`.

### Обычный git (если он установлен)

1. Убедитесь, что `data\` и `bin\*` не попадут в репозиторий — это уже есть
   в `.gitignore`.
2. Создайте репозиторий и выполните `init_repo.bat` — скрипт инициализирует
   git, сделает первый коммит и спросит адрес удалённого репозитория.
3. Остаётся выполнить:
   ```bat
   git push -u origin main
   ```

### Автоматическая сборка

Файл `.github/workflows/build-windows.yml` запускает тесты и собирает EXE
на Windows прямо в GitHub Actions — готовый архив доступен во вкладке
**Actions** → последний запуск → **Artifacts**.

Ядро sing-box, Wintun и пользовательские конфиги в репозиторий не попадают.

## Приватность

- Подписки, ключи и конфигурация хранятся **только локально** в `data\`.
- В логи не пишутся пароли, приватные ключи, UUID и другие секреты.
- Приложение не отправляет телеметрию и не обращается к сторонним сервисам,
  кроме ваших VPN-серверов, CDN замера скорости и ваших подписок.
- Системный прокси, включённый приложением, всегда снимается при отключении
  и при закрытии программы; если программа была убита — это делает сторож.
